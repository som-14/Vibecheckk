# VibeCheck Threat Model (STRIDE Methodology)

This document analyzes security risks, mitigations, verification mechanisms, and implementation statuses across the STRIDE threat categories. Status is labeled as **Implemented** only where functional code and passing automated tests exist in this repository; all other security controls are labeled as **Planned**.

## STRIDE Evaluation Matrix

| Category | Threat Description | Mitigation Strategy | How Verified | Status |
|---|---|---|---|---|
| **Spoofing** | Attacker attempts to forge creator identity, submit fake tokens, or brute-force user passwords. | Password verification using Argon2id with memory-hard parameters; authentication issues RS256-signed asymmetric JWTs expiring after 15 minutes. | Verified in `backend/tests/test_api.py::test_login_success` and `backend/tests/test_api.py::test_login_failure_wrong_password`. Code in `backend/auth.py`. | **Implemented** |
| **Tampering** | Attacker modifies JWT payload claims (e.g. altering `user_id` or `role`) or alters audit trail records. | RS256 signature verification guarantees payload integrity and rejects tampered signatures; PostgreSQL database role `app_role` explicitly revokes `UPDATE` and `DELETE` on `AuditLogs`. | Verified in `backend/tests/test_api.py::test_tampered_jwt_rejected`. Code in `backend/auth.py` and `db/procedures.sql`. | **Implemented** |
| **Repudiation** | User denies uploading a video, or administrator denies executing analytical tasks. | Database-level trigger `trg_audit_video_upload` automatically inserts immutable audit records upon upload; worker stored procedure records analysis creation. | Verified in `scripts/verify_full_flow.py` (Step 6 log audit confirmation). Code in `db/triggers.sql` and `db/procedures.sql`. | **Implemented** |
| **Information Disclosure** | Unhandled server exceptions leak internal tracebacks, password hashes are exposed in API payloads, or a creator reads another creator's video analysis. | Global exception handler suppresses stack traces returning generic 500 responses; user models omit password hashes from schemas; endpoint enforces owner check returning 403 Forbidden. | Verified in `backend/tests/test_api.py::test_creator_cannot_access_other_creator_video`. Code in `backend/main.py`. | **Implemented** |
| **Denial of Service** | Malicious client floods endpoints with requests, or uploads massive multi-gigabyte files to exhaust disk space and worker memory. | IP-based sliding window rate limiter restricts requests to 10 requests per minute returning 429; file validation enforces strict 50MB maximum upload limit returning 413. | Verified in `backend/tests/test_api.py::test_rate_limiting_11th_request_returns_429`. Code in `backend/rate_limiter.py` and `backend/main.py`. | **Implemented** |
| **Elevation of Privilege** | Creator attempts to invoke administrative endpoints (e.g. creator performance metrics view) or elevate account role. | Server-side role authorization dependency (`RequireRoles(["ADMIN"])`) checks decoded JWT claims against required permissions, returning 403 Forbidden. | Verified in `backend/tests/test_api.py::test_admin_can_read_any_video` and `test_creator_cannot_access_other_creator_video`. Code in `backend/auth.py`. | **Implemented** |
| **Cloud Secret Compromise** | Exposure of private encryption keys or database credentials in production cloud environment. | Centralized secrets storage using Azure Key Vault with Azure Managed Identities, eliminating static credentials in code and configuration files. | Documented design specification in `infra/azure-architecture.md`. | **Planned** |
| **Network Egress / Interception** | Man-in-the-middle network interception of media blobs or queue messages in cloud transit. | Azure Private Endpoints for PostgreSQL Flexible Server, Blob Storage, and Service Bus with enforced TLS 1.3 transport encryption. | Documented design specification in `infra/azure-architecture.md`. | **Planned** |
